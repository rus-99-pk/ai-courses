*   **Урок 7: Docker-контейнеризация и Хранение Данных**
    *   **Цель:** Освоить Docker для упаковки и запуска приложений, понять принципы работы с объектными хранилищами и безопасного хранения секретов.
    *   **Ключевые Темы:**
        *   Контейнеризация: История (chroot, jails, LXC), сравнение с VM.
        *   Docker: Архитектура (daemon, client, registry), образы (layers, Dockerfile), контейнеры.
        *   Dockerfile: Инструкции (`FROM`, `RUN`, `COPY`, `CMD`, `ENTRYPOINT`, `EXPOSE`, `ENV`), мультистейдж сборка.
        *   Docker Hub и Container Registries (Nexus/GitLab/другие): Публикация и получение образов.
        *   Docker Networking (basic): Bridge, Host, None.
        *   Docker Volumes: Управление персистентными данными контейнеров.
        *   Альтернативы Docker (обзор): Podman, containerd, CRI-O.
        *   Хранение данных: Блочные устройства vs Файловые системы vs Объектные хранилища.
        *   Объектные хранилища: Принципы S3 API.
        *   MinIO (как S3-совместимое хранилище): Установка, создание бакетов, загрузка/скачивание объектов.
        *   Безопасное хранение секретов: Проблемы хранения паролей, ключей в коде/конфигах.
        *   HashiCorp Vault: Архитектура (Server, Storage Backend), методы аутентификации, секретные движки (Key/Value).
    *   **Практические Задачи (Hands-on Labs):**
        1.  **Containerize Application:** Создать Dockerfile для вашего тестового приложения. Собрать Docker образ (`docker build`). Запустить контейнер из образа (`docker run`).
        2.  **Docker Hub/Registry:** Создать аккаунт на Docker Hub (или использовать Nexus/GitLab Registry). Залогиниться. Пометить образ (`docker tag`) и опубликовать его (`docker push`). Удалить локальный образ и скачать его из Registry (`docker pull`).
        3.  **Docker Volumes Practice:** Изменить Dockerfile/запуск контейнера для использования Volume для персистентного хранения данных (например, логов или файлов конфигурации, если применимо).
        4.  **MinIO Setup:** Развернуть MinIO. Создать бакет. Использовать MinIO Client (`mc`) или AWS CLI для взаимодействия с бакетом (загрузка, скачивание файлов).
        5.  **Vault Setup:** Развернуть Vault (в режиме dev или production с простым storage backend). Инициализировать и разблокировать Vault.
        6.  **Store Secrets in Vault:** Включить KV Secret Engine. Добавить секреты вашего приложения (например, учетные данные к БД, API ключи) в Vault.
        7.  **Integrate App with Vault:** Изменить код вашего приложения (или использовать скрипт запуска/библиотеку), чтобы оно получало свои секреты из Vault при старте.
        8.  **Update Pipeline:** Изменить CI/CD Pipeline:
            *   После сборки Maven, создать Docker образ.
            *   Пометить образ тегом (например, с номером билда или хешем коммита).
            *   Опубликовать образ в Container Registry.
            *   На этапе деплоя, вместо скачивания JAR/WAR, скачивать и запускать Docker образ. Пока можно просто на VM с Docker.
    *   **Результат:** Приложение упаковано в Docker образ, который автоматически собирается и публикуется. Умение использовать объектное хранилище для файлов и Vault для безопасного управления секретами. Пайплайн деплоит приложение как Docker контейнер.
