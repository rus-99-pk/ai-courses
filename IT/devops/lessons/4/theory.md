*   **Урок 4: Continuous Delivery и Continuous Deployment**
    *   **Цель:** Понять концепции CD/CD, научиться управлять артефактами и автоматизировать процесс доставки приложения на различные окружения.
    *   **Ключевые Темы:**
        *   Continuous Delivery (CD) vs Continuous Deployment (CD): В чем разница.
        *   Value Stream Management: Как увидеть и оптимизировать поток создания ценности.
        *   Delivery Pipeline: Расширение CI пайплайна на этапы деплоя (Dev, Stage, Prod).
        *   Системы хранения артефактов: Nexus Repository Manager (или JFrog Artifactory). Типы репозиториев (Maven, Docker, npm и т.д.).
        *   Twelve-Factor App Methodology: Принципы создания облачно-нативных приложений, которые легко деплоить и масштабировать.
        *   Стратегии развертывания: Rolling Update, Recreate, Blue/Green, Canary (введение).
        *   Откаты (Rollbacks): Почему нужны и как автоматизировать.
        *   Бэкапирование: Виды (полные, инкрементальные, дифференциальные), стратегии (снапшоты, копирование), ротации.
    *   **Практические Задачи (Hands-on Labs):**
        1.  **Nexus Setup:** Развернуть Nexus Repository Manager. Настроить репозитории для Maven артефактов и Docker образов (на будущее).
        2.  **Publish Artifacts:** Изменить Jenkins/GitLab CI Pipeline для публикации Maven артефакта (JAR/WAR) в Nexus после успешной сборки и тестов.
        3.  **Automate Deployment (Stage):** Добавить новый Stage в пайплайн (например, `Deploy to Staging`). Написать простой скрипт (Bash, Python), который скачивает последний артефакт из Nexus и деплоит его на тестовую VM (используя знания Урока 3). Интегрировать этот скрипт в пайплайн (например, с помощью SSH Agent в Jenkins или Runner в GitLab CI).
        4.  **Manual Promotion:** Настроить "ручной" шаг подтверждения (Manual Approval) в пайплайне перед деплоем на следующий этап (например, Production - пока чисто символически или на другую VM).
        5.  **Basic Rollback:** Добавить в пайплайн возможность откатить приложение на предыдущую успешную версию (например, с помощью скрипта, который деплоит предпоследний артефакт).
        6.  **Twelve-Factor App Check:** Проанализировать ваше тестовое приложение и оценить, насколько оно соответствует принципам 12-Factor App. Обсудить, как можно его улучшить (например, вынести конфиг из кода).
    *   **Результат:** Работающий Delivery Pipeline, который автоматически собирает, тестирует и деплоит приложение на тестовое окружение, сохраняет артефакты и позволяет вручную продвигать их дальше. Понимание важности автоматизации доставки и принципов 12-Factor App.
