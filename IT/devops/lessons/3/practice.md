**ТЕОРЕТИЧЕСКИЙ БЛОК (Краткий обзор)**

*   **Linux:** Ядро операционной системы. На его основе строятся различные дистрибутивы (Ubuntu, Debian, CentOS, Fedora, Alpine, Arch и т.д.) с разными наборами утилит, пакетными менеджерами (apt, yum/dnf, apk, pacman) и системами инициализации (systemd, SysVinit). Для DevOps важно уметь работать с командной строкой независимо от дистрибутива, хотя детали управления сервисами или пакетами могут отличаться.
*   **Файловая система Linux:** Иерархическая структура, начинающаяся с корня `/`. Понимание стандартных каталогов (`/bin`, `/sbin`, `/etc`, `/home`, `/var`, `/opt`, `/tmp`, `/usr`, `/proc`, `/sys`) критически важно.
*   **Права доступа:** Модель "владелец, группа, другие" (user, group, others) и три типа прав: чтение (read, `r`), запись (write, `w`), выполнение (execute, `x`). Представлены в символьном (rwx) или числовом (octal) виде (e.g., 755).
*   **Процессы и Сервисы:** Программа в состоянии выполнения - это процесс. Сервис (или демон) - это процесс, работающий в фоновом режиме, обычно запускающийся при старте системы и управляемый системой инициализации (systemd - современный стандарт).
*   **Сеть:** Набор компьютеров, соединенных для обмена данными. Основы:
    *   **IP-адрес:** Уникальный идентификатор устройства в сети (IPv4: 192.168.1.10, IPv6: 2001:db8::1).
    *   **Маска подсети:** Определяет, какая часть IP-адреса относится к сети, а какая к узлу (e.g., 255.255.255.0 или /24).
    *   **Шлюз по умолчанию (Gateway):** Устройство (обычно маршрутизатор), через которое пакеты отправляются в другие сети (в т.ч. Интернет).
    *   **DNS (Domain Name System):** Система преобразования доменных имен (google.com) в IP-адреса.
    *   **Порт:** Число (1-65535), используемое для идентификации конкретного приложения/сервиса на хосте (HTTP: 80, HTTPS: 443, SSH: 22).
    *   **Протоколы:** Набор правил для обмена данными. **TCP** (Transmission Control Protocol) - надежный, с установлением соединения. **UDP** (User Datagram Protocol) - быстрый, без гарантий доставки. **HTTP/HTTPS** - протоколы прикладного уровня для передачи веб-страниц.
*   **Файрвол (Firewall):** Система для контроля сетевого трафика, разрешающая или запрещающая соединения на основе правил (IP-адрес, порт, протокол). Популярные инструменты в Linux: `iptables` (старый, но мощный), `firewalld` (более новый, используемый в RHEL/CentOS), `ufw` (простой интерфейс для `iptables`, популярный в Ubuntu).
*   **SSH (Secure Shell):** Протокол и утилита для безопасного удаленного доступа к командной строке сервера. Использует шифрование. Аутентификация может быть по паролю или по паре ключей (публичный/приватный).
*   **Виртуализация:** Технология создания виртуальных версий ресурсов (серверов, хранилищ, сетей). **Гипервизор** - ПО, управляющее виртуальными машинами (Type 1 - работает напрямую на оборудовании: VMware ESXi, KVM; Type 2 - работает поверх ОС: VirtualBox, VMware Workstation). **Виртуальные машины** - эмуляция полноценного компьютера. **Виртуальные сети** - абстракция физической сети для виртуальных машин.

**ПРАКТИЧЕСКИЙ БЛОК (Hands-on Labs)**

**Lab 1: Linux CLI Mastery**

*   **Цель:** Отработать навыки работы с командной строкой, файлами, пользователями, правами доступа, процессами и фоновыми задачами.
*   **Шаги:**

    1.  **Базовые команды:**
        *   Подключитесь к вашей чистой VM по SSH.
        *   Изучите текущее положение: `pwd` (print working directory).
        *   Посмотрите содержимое каталога: `ls -lha` (подробный список, включая скрытые файлы, человекочитаемый размер).
        *   Перемещайтесь по каталогам: `cd /`, `cd ~`, `cd ..`, `cd -`.
        *   Создайте и удалите каталог: `mkdir mydir`, `rmdir mydir`. Создайте каталог с подкаталогом: `mkdir -p mydir/subdir`.
        *   Создайте файл: `touch myfile.txt`, `echo "Hello" > anotherfile.txt`.
        *   Скопируйте и переместите файл: `cp anotherfile.txt mydir/`, `mv mydir/anotherfile.txt mydir/renamedfile.txt`.
        *   Удалите файлы и каталоги: `rm myfile.txt`, `rm -r mydir` (рекурсивное удаление каталога), `rm -rf mydir` (принудительное рекурсивное удаление без запросов - *используйте осторожно!*).

    2.  **Поиск файлов и текста:**
        *   Найдите все файлы с расширением `.conf` в каталоге `/etc`:
            ```bash
            find /etc -name "*.conf"
            ```
        *   Найдите все файлы, измененные за последние 24 часа:
            ```bash
            find / -mtime -1
            ```
        *   Найдите файлы больше 100MB:
            ```bash
            find / -size +100M
            ```
        *   Найдите в файлах `/etc/*.conf` строки, содержащие слово "Port":
            ```bash
            grep "Port" /etc/*.conf
            ```
        *   Найдите строки, содержащие "PermitRootLogin" в файле `sshd_config` и покажите номер строки:
            ```bash
            grep -n "PermitRootLogin" /etc/ssh/sshd_config
            ```
        *   Найдите все файлы, содержащие слово "password", начиная из корня, игнорируя ошибки доступа:
            ```bash
            sudo grep -r "password" / 2>/dev/null
            ```

    3.  **Работа с пользователями и правами:**
        *   Посмотрите текущего пользователя и его группы: `whoami`, `id`.
        *   Посмотрите владельца и права файла/каталога: `ls -l`. Пример: `-rwxrw-r--` (владелец: rwx, группа: rw-, другие: r--).
        *   Создайте нового пользователя:
            ```bash
            sudo adduser testuser
            ```
            Введите пароль, информацию (можно пропустить).
        *   Переключитесь на нового пользователя: `su - testuser`. Посмотрите его домашний каталог (`pwd`) и права на него (`ls -ld ~`). Вернитесь к своему пользователю (`exit`).
        *   Смените владельца файла:
            ```bash
            touch myfile_for_chown.txt
            sudo chown testuser:testuser myfile_for_chown.txt
            ls -l myfile_for_chown.txt
            ```
        *   Смените права доступа к файлу/каталогу:
            ```bash
            # Добавить права на выполнение владельцу и группе, убрать запись у других
            chmod ug+x,o-w myfile_for_chown.txt
            # Установить права rwxr-xr-x (755)
            chmod 755 myfile_for_chown.txt
            ls -l myfile_for_chown.txt
            ```
        *   **Настройте беспарольный `sudo` для вашего основного пользователя:**
            *   Откройте файл конфигурации sudo с помощью `visudo`. Используйте `sudo visudo`. *Используйте именно `visudo`, а не просто текстовый редактор, т.к. он проверяет синтаксис.*
            *   Найдите строку, похожую на `%sudo ALL=(ALL:ALL) ALL` или `%wheel ALL=(ALL:ALL) ALL`.
            *   Добавьте под ней или отредактируйте существующую строку для вашего пользователя (замените `ваше_имя_пользователя`):
                ```
                ваше_имя_пользователя ALL=(ALL) NOPASSWD: ALL
                ```
            *   Сохраните файл и выйдите из редактора.
            *   Проверьте, можете ли вы выполнить команду с `sudo` без запроса пароля: `sudo apt update`.

    4.  **Управление процессами и сервисами:**
        *   Посмотрите список запущенных процессов: `ps aux`, `ps -ef`.
        *   Посмотрите дерево процессов: `ps faux`.
        *   Посмотрите процессы в реальном времени: `top`. Нажмите `q` для выхода. Установите `htop` (`sudo apt install htop` или `sudo yum install htop`) и запустите его (`htop`). Он более удобен.
        *   Найдите процесс по имени (например, sshd): `pgrep sshd`, `pkill -l sshd`.
        *   Остановите процесс (если у вас есть процесс, который можно безопасно остановить, например, запущенный вами скрипт или утилита): Найдите PID процесса (`ps aux | grep <имя_процесса>`), затем `kill PID`. Если не останавливается, попробуйте `kill -9 PID` (принудительное завершение).
        *   Посмотрите статус системного сервиса (например, sshd): `sudo systemctl status sshd`.
        *   Перезапустите сервис: `sudo systemctl restart sshd`.
        *   Включите/отключите автозапуск сервиса при загрузке: `sudo systemctl enable sshd`, `sudo systemctl disable sshd`.
        *   *Для старых систем инициализации (SysVinit)*: `sudo service sshd status`, `sudo service sshd restart`, `sudo chkconfig sshd on` (для CentOS/RHEL) или ручное редактирование символических ссылок (для Debian/Ubuntu).

    5.  **Фоновые задачи и персистентные сессии:**
        *   Запустите команду в фоне: `ping 8.8.8.8 > ping_log.txt &`. Вы увидите `[1] PID`.
        *   Посмотрите фоновые задачи в текущей сессии: `jobs`.
        *   Верните фоновую задачу на передний план: `fg %1` (где 1 - номер задачи).
        *   Снова отправьте задачу в фон (`Ctrl+Z`, затем `bg`).
        *   Запустите команду, которая продолжит работать после закрытия терминала (игнорировать сигнал HUP): `nohup ping 8.8.8.8 > nohup_ping_log.txt &`.
        *   Установите и используйте `screen` или `tmux` для создания персистентной сессии:
            ```bash
            # Установка (пример для Ubuntu):
            sudo apt install screen -y
            # Запуск новой сессии:
            screen # или tmux
            # Внутри сессии screen/tmux: запустите любую команду (например, top)
            # Отключиться от сессии (но оставить ее работать): Ctrl+A D (для screen) или Ctrl+B D (для tmux)
            # Посмотреть список запущенных сессий: screen -ls # или tmux ls
            # Подключиться обратно к сессии: screen -r # или tmux attach-session -t 0
            ```
            Это очень полезно для долгих процессов или когда нужно временно отключиться от сервера.

**Результат Lab 1:** Вы уверены в базовых командах Linux CLI, можете найти файлы, управлять процессами и сервисами, изменять права и работать с фоновыми задачами и сессиями.

**Lab 2: Управление Дисковой Системой (включая LVM)**

*   **Цель:** Научиться добавлять новые диски, партиционировать их, использовать LVM для гибкого управления томами и монтировать файловые системы.
*   **Шаги:**

    1.  **Добавьте второй виртуальный диск к вашей VM:**
        *   Выключите VM.
        *   В настройках вашего гипервизора (VirtualBox, VMware, Cloud console) добавьте новый виртуальный жесткий диск (например, размером 10GB).
        *   Включите VM.

    2.  **Определите новые диски:**
        *   Подключитесь по SSH.
        *   Посмотрите список дисков и их разделов: `lsblk`. Вы должны увидеть новый диск (например, `/dev/sdb`, если первый диск `/dev/sda` или `/dev/vda`). У него пока нет разделов.

    3.  **Партиционируйте новый диск для использования с LVM:**
        *   Используйте утилиту `fdisk` (или `parted` для дисков > 2TB или если предпочитаете Parted).
        ```bash
        sudo fdisk /dev/sdb # Замените /dev/sdb на имя вашего нового диска
        ```
        *   В интерактивном меню `fdisk`:
            *   Нажмите `n` для создания нового раздела (new partition).
            *   Выберите `p` для основного раздела (primary).
            *   Введите номер раздела (по умолчанию 1).
            *   Введите первый сектор (по умолчанию, нажмите Enter).
            *   Введите последний сектор или размер (по умолчанию, нажмите Enter, чтобы использовать весь диск, или укажите размер, например, `+10G`).
            *   Нажмите `t` для смены типа раздела (change partition type).
            *   Введите код типа раздела. Для Linux LVM это `8e`. (Нажмите `L` для просмотра списка кодов, если нужно).
            *   Нажмите `p` для просмотра таблицы разделов и убедитесь, что все правильно.
            *   Нажмите `w` для записи изменений на диск и выхода.
        *   Проверьте изменения: `lsblk`. Теперь у вас должен быть раздел `/dev/sdb1`.
        *   *Примечание:* Если вы используете облако, диски могут уже предоставляться как целые тома без необходимости партиционирования, готовые для LVM или форматирования.

    4.  **Настройте Logical Volume Management (LVM):**
        *   Установите пакет LVM, если он еще не установлен:
            ```bash
            # Ubuntu/Debian
            sudo apt install lvm2 -y
            # CentOS/RHEL/Fedora
            sudo yum install lvm2 -y
            ```
        *   Создайте физический том (Physical Volume) из вашего нового раздела:
            ```bash
            sudo pvcreate /dev/sdb1
            sudo pvs # Проверьте, что PV создан
            ```
        *   Создайте группу томов (Volume Group) из вашего физического тома:
            ```bash
            sudo vgcreate mydata_vg /dev/sdb1 # mydata_vg - имя вашей группы томов
            sudo vgs # Проверьте, что VG создан
            ```
        *   Создайте логический том (Logical Volume) из вашей группы томов:
            ```bash
            sudo lvcreate -L 8G -n mydata_lv mydata_vg # -L размер, -n имя тома, mydata_vg - группа томов
            sudo lvs # Проверьте, что LV создан
            ```
            Мы создали LV размером 8GB, оставив 2GB свободными в VG для будущего расширения.

    5.  **Отформатируйте и примонтируйте логический том:**
        *   Отформатируйте логический том с файловой системой (например, ext4):
            ```bash
            sudo mkfs.ext4 /dev/mydata_vg/mydata_lv
            ```
        *   Создайте точку монтирования:
            ```bash
            sudo mkdir /mnt/mydata
            ```
        *   Примонтируйте логический том к точке монтирования:
            ```bash
            sudo mount /dev/mydata_vg/mydata_lv /mnt/mydata
            ```
        *   Проверьте смонтированные файловые системы: `df -h`. Убедитесь, что `/mnt/mydata` виден.

    6.  **Настройте автоматическое монтирование при загрузке:**
        *   Получите UUID вашего нового логического тома (или раздела, если не используете LVM) для надежного монтирования:
            ```bash
            sudo blkid /dev/mydata_vg/mydata_lv
            # Или просто lsblk -f
            ```
            Скопируйте UUID.
        *   Отредактируйте файл `/etc/fstab` (файл таблицы файловых систем) с правами sudo:
            ```bash
            sudo nano /etc/fstab
            ```
        *   Добавьте в конец файла строку в формате: `UUID=<ваш_uuid> <точка_монтирования> <тип_ФС> <опции> <dump> <pass>`.
            ```
            UUID=ваш_uuid_скопированный_из_blkid /mnt/mydata ext4 defaults 0 2
            ```
            (Замените `ваш_uuid_скопированный_из_blkid` на реальный UUID).
        *   Сохраните файл и выйдите.
        *   Проверьте синтаксис `fstab` и попробуйте примонтировать все из него:
            ```bash
            sudo mount -a
            df -h # Убедитесь, что /mnt/mydata все еще примонтирован
            ```
        *   Перезагрузите VM (`sudo reboot`) и после подключения убедитесь, что `/mnt/mydata` автоматически примонтирован (`df -h`).

    7.  **Потренируйтесь в расширении логического тома LVM:**
        *   Проверьте свободное место в вашей группе томов: `sudo vgs`. У вас должно остаться около 2GB free.
        *   Расширьте логический том `mydata_lv` на 2GB:
            ```bash
            sudo lvextend -L +2G /dev/mydata_vg/mydata_lv
            sudo lvs # Проверьте новый размер LV
            ```
        *   **Расширьте файловую систему, чтобы использовать новое пространство LV:** *Это отдельный шаг!* Файловая система не расширяется автоматически вместе с LV.
            ```bash
            # Для файловой системы ext4:
            sudo resize2fs /dev/mydata_vg/mydata_lv
            # Для файловой системы XFS (часто используется в CentOS/RHEL):
            # sudo xfs_growfs /mnt/mydata # Указывается точка монтирования
            ```
        *   Проверьте доступное место: `df -h`. Убедитесь, что размер `/mnt/mydata` увеличился.

**Результат Lab 2:** Вы умеете добавлять и партиционировать диски, использовать LVM для гибкого создания и изменения логических томов, форматировать их и монтировать файловые системы, включая автоматическое монтирование при загрузке.

**Lab 3: Сетевая Диагностика и Базовый Файрвол**

*   **Цель:** Использовать сетевые утилиты для диагностики и настроить базовые правила файрвола.
*   **Шаги:**

    1.  **Анализ сетевых интерфейсов:**
        *   Посмотрите список сетевых интерфейсов и их IP-адреса: `ip addr show` или `ifconfig` (если `ifconfig` не установлен, установите пакет `net-tools`).
        *   Посмотрите таблицу маршрутизации (куда отправляется трафик): `ip route show` или `netstat -r`. Найдите шлюз по умолчанию (`default via ...`).
        *   Посмотрите настройки DNS сервера: `cat /etc/resolv.conf`.

    2.  **Сетевые утилиты для диагностики:**
        *   Проверьте связность с другим узлом (например, шлюзом или внешним IP): `ping 8.8.8.8` (DNS Google). Прервите командой `Ctrl+C`.
        *   Отследите маршрут до удаленного узла: `traceroute google.com` (или `mtr google.com` - более продвинутая утилита, возможно, потребуется установить).
        *   Посмотрите, какие порты слушает ваша VM: `sudo netstat -tulnp` или `sudo ss -tulnp`. Убедитесь, что SSH (`:22`) слушается.
        *   Проверьте доступность веб-страницы: `curl google.com`, `wget google.com`. Попробуйте получить только HTTP заголовки: `curl -I google.com`.
        *   *Опционально:* Базовый захват трафика (только для ознакомления, tcpdump мощная утилита):
            ```bash
            # Установите tcpdump
            sudo apt install tcpdump -y # или yum install tcpdump -y
            # Захватите ICMP пакеты (используемые ping) на интерфейсе вашей VM (например, eth0)
            sudo tcpdump -i eth0 -n icmp
            # В другом терминале пинганите вашу VM или внешний ресурс. Увидите пакеты.
            # Остановите tcpdump командой Ctrl+C.
            ```

    3.  **Настройка файрвола (UFW или Firewalld):** *Используйте один из них, в зависимости от вашего дистрибутива (UFW в Ubuntu, Firewalld в CentOS по умолчанию), или выберите удобный.*

        *   **Использование UFW (Uncomplicated Firewall - Ubuntu):**
            *   Проверьте статус UFW: `sudo ufw status`. Скорее всего, он неактивен.
            *   Разрешите входящие соединения по SSH (порт 22): `sudo ufw allow ssh` или `sudo ufw allow 22`.
            *   Разрешите входящие соединения по HTTP (порт 80) и HTTPS (порт 443), если планируете деплоить веб-приложение: `sudo ufw allow http`, `sudo ufw allow https`.
            *   Включите UFW: `sudo ufw enable`. Вам может быть показано предупреждение о прерывании SSH соединения - подтвердите.
            *   Снова проверьте статус: `sudo ufw status verbose`. Убедитесь, что правила добавлены и файрвол активен.
            *   Проверьте, можете ли вы по-прежнему подключиться по SSH. Если нет, возможно, правило SSH не применилось или вы случайно заблокировали свой IP. В этом случае может потребоваться доступ через консоль гипервизора для отключения файрвола (`sudo ufw disable`).

        *   **Использование Firewalld (CentOS/RHEL):**
            *   Проверьте статус Firewalld: `sudo systemctl status firewalld`. Скорее всего, он активен по умолчанию.
            *   Посмотрите активные зоны и разрешенные сервисы/порты: `sudo firewall-cmd --get-active-zones`.
            *   Посмотрите разрешенные сервисы/порты в нужной зоне (например, public): `sudo firewall-cmd --zone=public --list-services`, `sudo firewall-cmd --zone=public --list-ports`.
            *   Разрешите входящие соединения по SSH (сервис `ssh`): `sudo firewall-cmd --zone=public --add-service=ssh --permanent`. ( `--permanent` делает правило постоянным после перезагрузки).
            *   Разрешите входящие соединения по HTTP (сервис `http`) и HTTPS (`https`), если планируете деплоить веб-приложение: `sudo firewall-cmd --zone=public --add-service=http --permanent`, `sudo firewall-cmd --zone=public --add-service=https --permanent`.
            *   Перезагрузите Firewalld для применения *постоянных* правил: `sudo firewall-cmd --reload`.
            *   Снова проверьте разрешенные сервисы: `sudo firewall-cmd --zone=public --list-services`. Убедитесь, что `ssh`, `http`, `https` добавлены.

**Результат Lab 3:** Вы можете использовать базовые сетевые утилиты для анализа и диагностики, а также настраивать простые правила файрвола для контроля доступа к сервисам на VM.

**Lab 4: Настройка Аутентификации SSH по Ключам**

*   **Цель:** Настроить безопасный вход на сервер по SSH без использования пароля, используя пару ключей.
*   **Шаги:**

    1.  **Сгенерируйте пару SSH ключей на *вашей рабочей машине*:**
        *   Откройте терминал на вашей рабочей машине.
        *   Выполните команду:
            ```bash
            ssh-keygen -t rsa -b 4096 -C "ваше_имя_пользователя@имя_вашей_рабочей_машины"
            ```
            *   `-t rsa`: Тип ключа (RSA).
            *   `-b 4096`: Размер ключа в битах (рекомендуется 4096 для RSA).
            *   `-C "..."`: Комментарий (полезно для идентификации ключа).
        *   Система спросит, куда сохранить ключи. Нажмите Enter для использования пути по умолчанию (`~/.ssh/id_rsa`).
        *   Система предложит ввести парольную фразу (passphrase). **Настоятельно рекомендуется использовать парольную фразу.** Она защищает ваш приватный ключ, если он попадет не в те руки. Введите и подтвердите фразу.
        *   Будет сгенерировано два файла: `~/.ssh/id_rsa` (ваш приватный ключ) и `~/.ssh/id_rsa.pub` (ваш публичный ключ). **Никогда никому не давайте ваш приватный ключ (`id_rsa`)!**

    2.  **Скопируйте публичный ключ на вашу VM:**
        *   Самый простой способ - использовать утилиту `ssh-copy-id`.
            ```bash
            ssh-copy-id ваше_имя_пользователя@IP_АДРЕС_VM
            ```
            Вам будет предложено ввести пароль вашего пользователя на VM. После успешной аутентификации `ssh-copy-id` добавит содержимое файла `~/.ssh/id_rsa.pub` с вашей рабочей машины в файл `~/.ssh/authorized_keys` на VM.
        *   *Альтернативный способ (если `ssh-copy-id` недоступен или не работает):*
            ```bash
            # На вашей рабочей машине:
            cat ~/.ssh/id_rsa.pub
            ```
            Скопируйте вывод (весь текст, начинающийся с `ssh-rsa ...` и заканчивающийся комментарием).
            ```bash
            # На вашей VM (подключитесь по паролю):
            mkdir ~/.ssh # Если каталог не существует
            chmod 700 ~/.ssh # Убедитесь, что права правильные
            nano ~/.ssh/authorized_keys # Создайте или отредактируйте файл
            # Вставьте скопированный публичный ключ на новую строку
            chmod 600 ~/.ssh/authorized_keys # Убедитесь, что права правильные
            ```

    3.  **Проверьте вход по SSH без пароля:**
        *   Откройте новый терминал на вашей рабочей машине (чтобы убедиться, что нет кэшированных данных аутентификации).
        *   Попробуйте подключиться к VM:
            ```bash
            ssh ваше_имя_пользователя@IP_АДРЕС_VM
            ```
        *   Система должна запросить *парольную фразу* для вашего приватного ключа (если вы ее задавали), но *не* пароль пользователя на VM. После ввода фразы вы должны войти.
        *   Если вы используете `ssh-agent` (обычно работает по умолчанию в современных ОС), парольную фразу могут спросить только при первом использовании ключа после загрузки рабочей станции.

    4.  **(Опционально, но рекомендуется) Отключите аутентификацию по паролю на VM:** Это повышает безопасность, т.к. брутфорс паролей становится невозможен.
        *   **Убедитесь, что вход по ключу работает надежно, и у вас есть другие способы доступа (например, консоль гипервизора!) на случай проблем.**
        *   Подключитесь к VM по SSH (по ключу).
        *   Отредактируйте файл конфигурации SSH демона с правами sudo:
            ```bash
            sudo nano /etc/ssh/sshd_config
            ```
        *   Найдите строку `PasswordAuthentication` и измените ее на `no`. Если строка закомментирована (`#PasswordAuthentication yes`), раскомментируйте ее и измените на `no`.
            ```ini
            PasswordAuthentication no
            ```
        *   Найдите строку `PermitRootLogin` и убедитесь, что она установлена в `no` или `prohibit-password` (для безопасности).
        *   Сохраните файл и выйдите.
        *   Примените изменения, перезапустив службу SSH:
            ```bash
            sudo systemctl restart sshd
            ```
        *   Откройте *новый* терминал на рабочей машине и попробуйте подключиться по SSH. Убедитесь, что теперь войти можно только по ключу (или с запросом парольной фразы ключа), а запрос пароля пользователя VM не появляется вообще.

**Результат Lab 4:** У вас настроен безопасный доступ к VM по SSH с использованием пары ключей, и вы отключили менее безопасный вход по паролю. Это стандартная практика в DevOps.

**Lab 5: Ручное Развертывание Приложения на VM**

*   **Цель:** Закрепить полученные знания о Linux, вручную развернув простое приложение на чистой VM. Это упражнение покажет, какие шаги нужно будет автоматизировать в дальнейшем.
*   **Предварительные требования:**
    *   Чистая VM (можно использовать новую или сбросить ту, которую использовали до этого, чтобы начать с чистого листа).
    *   Установленный JDK (как в Технической подготовке).
    *   Собранный JAR/WAR файл вашего Maven проекта из Урока 1/2.
    *   Настроенный SSH доступ по ключу к этой VM (Lab 4).
*   **Шаги:**

    1.  **Подключитесь к VM по SSH.**

    2.  **Создайте каталог для приложения:** Хорошей практикой является установка приложений в `/opt`.
        ```bash
        sudo mkdir /opt/myjavaapp
        sudo chown ваше_имя_пользователя:ваше_имя_пользователя /opt/myjavaapp # Дать вашему пользователю права на этот каталог
        ```
        (Или дайте права группе, если в будущем приложение будет запускаться от имени специального пользователя).

    3.  **Скопируйте артефакт (JAR/WAR) на VM:** Сделайте это с вашей рабочей машины, используя `scp`.
        ```bash
        # На вашей рабочей машине
        scp /path/to/your/my-app/target/my-app-1.0-SNAPSHOT.jar ваше_имя_пользователя@IP_АДРЕС_VM:/opt/myjavaapp/
        ```
        (Замените путь и имя файла на актуальные для вашего проекта).

    4.  **Перейдите в каталог приложения на VM:**
        ```bash
        cd /opt/myjavaapp
        ```
        Проверьте, что файл скопировался (`ls -lh`).

    5.  **Запустите приложение:**
        ```bash
        java -jar my-app-1.0-SNAPSHOT.jar
        ```
        (Замените имя файла на актуальное). Если приложение требует каких-либо специфических настроек (например, параметры подключения к базе данных), возможно, вам придется передать их как аргументы командной строки или переменные окружения, в зависимости от того, как ваше приложение их читает. Например:
        ```bash
        java -Dspring.datasource.url=... -jar my-app-1.0-SNAPSHOT.jar
        ```
        *Проблема:* Приложение запущено, но оно блокирует ваш текущий терминал. Если вы закроете SSH сессию, приложение остановится.

    6.  **Запустите приложение в фоновом режиме, чтобы оно не остановилось:**
        ```bash
        nohup java -jar my-app-1.0-SNAPSHOT.jar > app.log 2>&1 &
        ```
        *   `nohup`: Игнорировать сигнал SIGHUP (который отправляется при закрытии терминала).
        *   `> app.log`: Перенаправить стандартный вывод в файл `app.log`.
        *   `2>&1`: Перенаправить стандартный поток ошибок (stderr, дескриптор 2) в тот же файл, куда перенаправлен стандартный вывод (stdout, дескриптор 1).
        *   `&`: Запустить команду в фоновом режиме.
        Вы увидите PID процесса. Можете закрыть SSH сессию и снова подключиться, процесс должен продолжать работать (`ps aux | grep java`). Логи будут писаться в файл `app.log` в текущем каталоге (`tail -f app.log`).

    7.  **(Опционально) Проверьте, доступно ли приложение:** Если ваше приложение - веб-сервис, проверьте его доступность через `curl` на VM (`curl localhost:ПОРТ_ПРИЛОЖЕНИЯ`) или извне VM (убедитесь, что файрвол разрешает доступ к этому порту!).

    8.  **Остановите приложение:** Найдите PID процесса (`ps aux | grep my-app`), затем `kill PID`.

**Результат Lab 5:** Вы получили ценный опыт ручного развертывания приложения на сервере, выполняя все шаги самостоятельно. Это наглядно демонстрирует, почему в DevOps мы стремимся к автоматизации этих процессов.
