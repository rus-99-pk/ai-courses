# 6. Лучшие практики, решение проблем и мониторинг CephFS

Стабильная работа CephFS в Kubernetes требует внимания к состоянию MDS и правильной диагностики проблем.

## Лучшие практики (Best Practices)

1.  **Высокая доступность MDS**: Всегда запускайте несколько Metadata Servers (MDS) для каждой файловой системы. Установите `max_mds` > 1 для активной/активной конфигурации (улучшает производительность) или `num_standby` > 0 для активной/пассивной (для отказоустойчивости). [3]
2.  **Мониторинг MDS**: MDS — это мозг CephFS. Следите за его нагрузкой по CPU и использованию памяти. Перегруженный MDS — основная причина снижения производительности файловой системы. Используйте `ceph dashboard` или Prometheus/Grafana для мониторинга.
3.  **Используйте квоты**: Всегда указывайте размер в PVC, чтобы CSI-драйвер устанавливал квоты на `subvolumes`. Это предотвратит исчерпание всего пространства одним приложением.
4.  **Разделяйте рабочие нагрузки**: По возможности, используйте разные файловые системы CephFS или `subvolume` группы для разных типов нагрузок (например, одна для логов, другая для медиафайлов), чтобы изолировать их друг от друга.
5.  **Ядерный клиент vs FUSE**: CSI-драйвер по умолчанию использует ядерный клиент `ceph` для монтирования, что обеспечивает лучшую производительность. Убедитесь, что на ваших рабочих узлах установлены `ceph-common` (или `ceph-fuse`) и поддерживается необходимое ядро. [1]

## Распространенные ошибки (Bad Practices)

1.  **Один MDS в продакшене**: Запуск одного MDS — это создание единой точки отказа. При его падении вся файловая система станет недоступной.
2.  **Использование `adminKey` для монтирования**: В `StorageClass` для `node-stage-secret` должен быть указан секрет с `userID`/`userKey`, а не с `adminID`/`adminKey`. Ключ администратора нужен только для `provisioner` и `snapshotter`.
3.  **Игнорирование состояния Ceph**: Запуск `ceph health` должен быть регулярной практикой. Проблемы с OSD или PG напрямую влияют на производительность и доступность CephFS.
4.  **Слишком много маленьких файлов**: CephFS, как и многие распределенные ФС, лучше работает с файлами большего размера. Очень большое количество мелких файлов создает высокую нагрузку на MDS.

## Решение проблем (Troubleshooting)

### Проблема: PVC застрял в статусе `Pending`

**Диагностика:**
1.  **Посмотрите логи прови저нера:**
    ```bash
    kubectl logs -l app=csi-cephfsplugin-provisioner -c csi-provisioner -n <namespace>
    ```
    Ищите ошибки, связанные с `fsName`, правами доступа `adminKey` или невозможностью создать `subvolume`.
2.  **Проверьте статус CephFS:**
    ```bash
    ceph fs status
    ```
    Убедитесь, что MDS в состоянии `active` и нет ошибок.

### Проблема: Под не может запуститься, ошибка `MountVolume.SetUp failed`

**Диагностика:**
1.  **Посмотрите логи `csi-cephfsplugin` на проблемном узле:**
    ```bash
    # Находим под CSI-драйвера на нужном узле
    kubectl get pods -l app=csi-cephfsplugin --field-selector spec.nodeName=<node-name> -n <namespace>
    # Смотрим его логи
    kubectl logs <csi-cephfsplugin-pod-name> -c csi-cephfsplugin -n <namespace>
    ```
    Частые ошибки: `mount error: No such file or directory` (неправильный путь или `fsName`) или `mount error: Permission denied` (неправильный `userKey`).
2.  **Проверьте сетевую связность с узла:**
    Убедитесь, что с рабочего узла Kubernetes доступны IP-адреса и порты мониторов Ceph.
    ```bash
    # На узле
    ping <monitor_ip>
    telnet <monitor_ip> 6789
    ```
3.  **Попробуйте смонтировать вручную:**
    Зайдите на узел и попробуйте выполнить команду монтирования, которую использует драйвер. Это поможет точно локализовать проблему.
    ```bash
    # Пример команды
    mount -t ceph <mon_ip1>,<mon_ip2>:/path/to/subvolume /mnt -o name=kube,secret=<userKey>
    ```

### Проблема: Низкая производительность (тормозят операции с файлами)

**Диагностика:**
1.  **Проверьте нагрузку на MDS:**
    ```bash
    ceph tell mds.* perf dump
    ```
    Смотрите на количество запросов в очереди и время их обработки.
2.  **Проверьте состояние OSD:**
    Медленные или перегруженные OSD будут тормозить всю систему.
    ```bash
    ceph osd perf
    ```
3.  **Сетевые задержки**: Проверьте задержки (ping) между клиентами (узлами K8s) и серверами Ceph (MON, MDS, OSD).
