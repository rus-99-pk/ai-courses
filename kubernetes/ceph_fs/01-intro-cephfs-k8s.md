# 1. Введение в CephFS и его роль в Kubernetes

Этот раздел объясняет, что такое CephFS, чем он отличается от блочного хранилища RBD и какие задачи он решает в экосистеме Kubernetes.

## Что такое CephFS?

**CephFS** — это POSIX-совместимая, распределенная файловая система, построенная поверх объектного хранилища Ceph (RADOS). [1] В отличие от Ceph RBD, который предоставляет "сырые" блочные устройства, CephFS предоставляет иерархическую файловую систему, к которой можно получить доступ с нескольких клиентов одновременно. [1, 2]

Ключевым компонентом CephFS является **Metadata Server (MDS)**. [1] MDS управляет метаданными файлов (имена, директории, права доступа), в то время как сами данные файлов хранятся в виде объектов непосредственно в кластере Ceph. [3] Такая архитектура позволяет CephFS быть высокопроизводительной и масштабируемой. Для отказоустойчивости можно запускать несколько MDS в активном/резервном режиме. [1, 3]

## CephFS vs Ceph RBD: Ключевые отличия

| Характеристика | Ceph RBD (Блочное хранилище) | CephFS (Файловое хранилище) |
| :--- | :--- | :--- |
| **Тип доступа** | Блочное устройство (как жесткий диск) | Файлы и директории (как NFS) |
| **Основной режим** | `ReadWriteOnce` (RWO) | `ReadWriteMany` (RWX) |
| **Сценарий** | Базы данных, очереди сообщений (один "писатель") | Веб-серверы с общим контентом, загрузка файлов, аналитика |
| **Структура** | "Плоский" образ | Иерархия файлов и папок |
| **Управление** | Управление образами (images) | Управление файлами и квотами на директории |

## Зачем использовать CephFS с Kubernetes?

Главное преимущество CephFS в контексте Kubernetes — это нативная поддержка режима доступа **`ReadWriteMany` (RWX)**. [2]

**Задача, которую мы решаем:** Представьте, что у вас есть веб-приложение (например, WordPress или Drupal), развернутое в виде `Deployment` с несколькими репликами (подами). Все эти поды должны иметь доступ к одной и той же директории с файлами (например, загруженные медиафайлы, плагины, темы).

*   С **RBD (RWO)** это невозможно. Только один под сможет смонтировать том для записи. Остальные не смогут запуститься.
*   С **CephFS (RWX)** все поды могут одновременно монтировать один и тот же том для чтения и записи. [2]

Другие преимущества:

*   **Динамическое выделение**: Как и в случае с RBD, Kubernetes может автоматически создавать поддиректории (subvolumes) в CephFS по запросу через PVC. [6]
*   **Гибкость**: Не нужно заранее определять точный размер тома. CephFS — это единое пространство, а квоты можно применять для ограничения использования.
*   **Единое пространство имен**: Все данные доступны в рамках одной файловой системы, что упрощает управление.
*   **Снэпшоты**: CSI-драйвер позволяет делать снэпшоты отдельных поддиректорий (subvolumes). [9]

## Архитектура интеграции

Интеграция Kubernetes и CephFS, так же как и с RBD, осуществляется через **CSI-драйвер `ceph-csi`**. [1, 6] Архитектура идентична:

1.  **CSI Controller Plugin**: Отвечает за создание/удаление `subvolumes` в CephFS и управление объектами `PersistentVolume`.
2.  **CSI Node Plugin**: Запускается на каждом узле и отвечает за монтирование файловой системы CephFS в нужную директорию пода.

Процесс выглядит так:
1.  Пользователь создает PVC с `accessModes: ReadWriteMany`.
2.  CSI-контроллер создает в CephFS специальную директорию (`subvolume`).
3.  Когда поды, использующие этот PVC, планируются на разные узлы, CSI-плагин на каждом из этих узлов выполняет команду `mount` для подключения общего каталога CephFS.
