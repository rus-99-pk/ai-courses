## Модуль 3: Развертывание тестового приложения (Bookinfo)

Для экспериментов нам нужно приложение, которое имитирует реальную микросервисную архитектуру. `Bookinfo` — это не просто "Hello World", это полноценный **полиглот-сервис**.

**Архитектура приложения:**
1.  **Productpage (Python):** Фронтенд, который генерирует HTML-страницу.
2.  **Details (Ruby):** Содержит информацию о книгах.
3.  **Reviews (Java):** Содержит отзывы. Имеет 3 версии:
    *   v1: Нет звезд.
    *   v2: Черные звезды.
    *   v3: Красные звезды.
4.  **Ratings (Node.js):** Хранит оценки (сами звезды).

**Зачем нам эта сложность?**
Чтобы доказать, что **Istio всё равно, на каком языке написан ваш сервис**. Istio работает на сетевом уровне (TCP/HTTP), ему не важно, Java это или Python. Все функции (метрики, тайм-ауты, ретраи) будут работать одинаково для всех языков без изменения кода приложения.

### 3.1 Механизм Sidecar Injection (Теория)
В классическом Istio (не Ambient) используется паттерн **Sidecar** (мотоцикл с коляской).
*   **Мотоцикл** — это ваш контейнер с приложением (например, `productpage`).
*   **Коляска** — это контейнер `istio-proxy` (на базе Envoy).

**Как это работает:**
Мы не добавляем прокси вручную в каждый Deployment. Мы просто вешаем "метку" на весь Namespace. Когда Kubernetes пытается создать под, Istio "видит" эту метку и через механизм *MutatingAdmissionWebhook* на лету внедряет контейнер с прокси внутрь пода, еще до его запуска.

В итоге, **весь входящий и исходящий трафик** вашего контейнера принудительно заворачивается в Proxy. Приложение думает, что общается с сетью, а на самом деле общается с Envoy.

### 3.2 Создание Namespace и активация инъекции
```bash
# Создаем пространство имен для нашего теста
kubectl create namespace bookinfo

# Включаем автоматическое внедрение sidecar-контейнеров
# Именно эта команда говорит Istio: "Следи за этим неймспейсом"
kubectl label namespace bookinfo istio-injection=enabled
```
*Проверка:*
```bash
kubectl get ns bookinfo --show-labels
```
Убедитесь, что метка `istio-injection=enabled` присутствует.

### 3.3 Деплой приложения
Мы используем стандартный манифест Kubernetes. В нем нет ни слова про Istio. Это обычные Deployments и Services.

```bash
# Применяем манифест из официального репозитория Istio
kubectl apply -n bookinfo -f https://raw.githubusercontent.com/istio/istio/master/samples/bookinfo/platform/kube/bookinfo.yaml
```

### 3.4 Проверка установки (Важный момент!)
Подождите 1-2 минуты, пока скачаются образы. Затем проверьте поды:

```bash
kubectl get pods -n bookinfo
```

**Разбор вывода:**
Вы должны увидеть картину, похожую на эту:
```text
NAME                              READY   STATUS    RESTARTS   AGE
details-v1-79f774bdb9-xxxxx       2/2     Running   0          2m
productpage-v1-6b746f74dc-xxxxx   2/2     Running   0          2m
ratings-v1-b6994bb9-xxxxx         2/2     Running   0          2m
reviews-v1-545db77b95-xxxxx       2/2     Running   0          2m
reviews-v2-7bf8c9648f-xxxxx       2/2     Running   0          2m
reviews-v3-84779c7bbc-xxxxx       2/2     Running   0          2m
```

**На что смотреть:**
Главное — столбец **READY 2/2**.
*   `1/2` означает, что один контейнер запустился, а второй еще нет. Обычно `istio-proxy` стартует быстрее, а приложение (Java/Node) тупит. Это нормально.
*   `2/2` означает полный успех. Один контейнер — ваш код, второй — Envoy Proxy.

> **Если вы видите `1/1`:**
> Значит, вы забыли поставить лейбл `istio-injection=enabled` **до** того, как создали поды. Istio не умеет внедряться в уже запущенные поды.
> *Решение:* Поставьте лейбл и удалите поды (`kubectl delete pods --all -n bookinfo`). Deployment пересоздаст их, и на этот раз инъекция сработает.

### 3.5 Проверка сервисов
Убедитесь, что обычные Kubernetes Service тоже создались:
```bash
kubectl get svc -n bookinfo
```
Вы увидите `details`, `productpage`, `ratings`, `reviews`. У них нет внешних IP (ClusterIP), и это правильно. Мы не будем открывать их через NodePort или LoadBalancer. Весь доступ извне пойдет **только** через Istio Gateway, который мы настроим в следующем модуле.
