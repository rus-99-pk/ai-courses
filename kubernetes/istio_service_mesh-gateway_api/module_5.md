## Модуль 5: Визуализация (Kiali, Grafana, Prometheus)

Это самая эффектная часть курса. До этого мы работали в "консольной темноте". Теперь мы включим свет.

**В чем суть Observability (Наблюдаемости)?**

Istio автоматически собирает телеметрию с каждого запроса, проходящего через Envoy Proxy. Вам не нужно дописывать код в приложение, чтобы узнать RPS, количество ошибок или время отклика.

### 5.1 Генерация нагрузки (Traffic Generation)
Графики пусты, когда системой никто не пользуется. Чтобы увидеть красоту, нам нужен постоянный поток запросов.

Откройте **новое окно терминала** и запустите этот бесконечный цикл. Он будет дергать наш шлюз (настроенный в Модуле 4) каждые полсекунды.

```bash
# Убедитесь, что port-forward из модуля 4 все еще работает!
# Если нет — запустите его снова: kubectl port-forward -n bookinfo svc/bookinfo-gateway 8080:80

# Цикл нагрузки:
while true; do 
  curl -s -o /dev/null "http://localhost:8080/productpage"
  echo -n "." # Чтобы видеть, что процесс идет
  sleep 0.5
done
```

### 5.2 Kiali — Топология и Связи
Kiali — это "Control Tower" вашего меша. Она визуализирует структуру микросервисов в реальном времени.

```bash
istioctl dashboard kiali
```
*Команда откроет браузер. Если нет — перейдите на `http://localhost:20001`.*

**Практикум настройки Графа:**

По умолчанию граф может быть пустым или неинформативным. Давайте настроим его правильно:

1.  В левом меню выберите **Graph**.
2.  Сверху в выпадающем списке `Namespace` выберите **bookinfo**.
3.  Рядом с неймспейсом выберите тип графа: **Versioned app graph**.
    *   *Зачем:* Чтобы видеть v1, v2, v3 как отдельные узлы.
4.  Нажмите кнопку **Display** (меню настройки отображения) и поставьте галочки:
    *   `Traffic Animation` (Летящие точки показывают поток).
    *   `Security` (Показывает замочки mTLS).
    *   `Traffic Rate` -> `Requests per second`.
    *   `Response Time` (Время ответа).

**Что мы видим:**
*   **Дерево вызовов:** Вы четко видите путь: `Gateway` -> `productpage` -> `reviews` (расходится на 3 версии) -> `ratings`.
*   **mTLS:** Зеленые замочки на линиях означают, что трафик между подами зашифрован. Мы ничего для этого не делали, Istio включил это сам.
*   **Распределение:** Вы видите, что трафик на `reviews` делится примерно поровну (33%) между v1, v2 и v3.

### 5.3 Grafana — Аналитика и Метрики
Если Kiali — это карта, то Grafana — это приборная панель с детальными цифрами.

```bash
istioctl dashboard grafana
```
*Откроется на `http://localhost:3000`.*

**Работа с дашбордами:**
1.  Нажмите на иконку поиска (лупа) или меню Dashboards.
2.  Зайдите в папку **Istio**.
3.  Выберите **Istio Service Dashboard**.
4.  Вверху выберите Service: `productpage.bookinfo.svc.cluster.local`.

**Разбор "Золотых сигналов" (Golden Signals):**
*   **Client Request Volume (RPS):** Нагрузка на сервис. Должно быть около 2 ops/s (наш цикл curl).
*   **Client Success Rate:** Должен быть 100%. Если видите падение — значит, летят 500-е ошибки.
*   **Client Request Duration (Latency):** Самый важный график.
    *   `P50` (медиана): Обычное время ответа.
    *   `P99` (хвост): Время ответа для самых медленных 1% запросов. В продакшене смотрят именно на P99, так как именно эти "тормоза" раздражают пользователей.

### 5.4 Prometheus (Опционально)
Все графики выше строятся на данных из Prometheus. Вы можете заглянуть в "сырые" данные.

```bash
istioctl dashboard prometheus
```
В поле запроса введите:
`istio_requests_total{destination_service="reviews.bookinfo.svc.cluster.local"}`
Нажмите **Execute**.

Вы увидите список метрик с кучей лейблов (`source_workload`, `response_code` и т.д.). Именно эти лейблы позволяют Grafana рисовать красивые графики, фильтруя данные по версиям и кодам ответов.
