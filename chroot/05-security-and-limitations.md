# Модуль 5: Безопасность и ограничения

`chroot` — полезный инструмент, но его часто ошибочно считают надежным средством для изоляции безопасности, как Docker или виртуальные машины. Это не так.

### Почему `chroot` — это не панацея?

Основная проблема: **`chroot` изолирует только файловую систему, а не ядро.**

Процесс, запущенный в chroot, по-прежнему взаимодействует с тем же ядром Linux, что и все остальные процессы в системе. Если этот процесс запущен от имени `root`, он сохраняет все свои привилегии.

### Способы "побега" из chroot

Если злоумышленник получил права `root` внутри chroot-окружения, он может попытаться "сбежать". Вот классические примеры:

1.  **Создание файла устройства**: Имея права `root`, можно создать файл устройства (`mknod`) для реального жесткого диска (`/dev/sda1`), примонтировать его и получить доступ ко всей файловой системе.
2.  **Использование `chdir("..")` в цикле**: Старые версии некоторых ядер позволяли с помощью многократного вызова `chdir("..")` в специально написанной программе на C "выйти" за пределы chroot. Сейчас это в основном исправлено.
3.  **Взаимодействие с другими процессами**: Процесс в chroot может отправлять сигналы другим процессам вне "тюрьмы" (например, `kill`).
4.  **Сетевые подключения**: Процесс может открывать сетевые сокеты и взаимодействовать с внешним миром без ограничений.

**Главный вывод**: `chroot` **не** предназначен для сдерживания недоверенного пользователя с правами `root`. Он предназначен для ограничения пользователя **без** root-прав или для запуска доверенного процесса с пониженными привилегиями.

### Рекомендации по безопасному использованию

1.  **Сбрасывайте привилегии**: Самая важная практика. Программа должна запускаться с правами `root` только для выполнения вызова `chroot()`. Сразу после этого она должна сбросить свои привилегии до непривилегированного пользователя (например, с помощью вызовов `setgid()` и `setuid()`). Так работают многие серверные приложения (Apache, Nginx).

2.  **Минимализм**: Включайте в chroot-окружение только абсолютно необходимые файлы. Не кладите туда компиляторы (`gcc`), интерпретаторы (`python`, `perl`), сетевые утилиты (`wget`, `nc`) или редакторы, если они не нужны для работы приложения. Чем меньше инструментов у злоумышленника, тем лучше.

3.  **Используйте в комбинации**: `chroot` отлично работает в связке с другими механизмами безопасности Linux:
    *   **Namespaces (пространства имен)**: основа современных контейнеров (Docker, LXC). Изолируют не только ФС, но и процессы (PID), сеть, пользователей (UID) и т.д.
    *   **Seccomp**: Ограничивает системные вызовы, которые может делать процесс.
    *   **AppArmor/SELinux**: Мандатный контроль доступа, который определяет, к каким файлам и ресурсам может обращаться процесс.

Современные контейнеры — это, по сути, `chroot` на стероидах, усиленный пространствами имен, cgroups и другими технологиями.
