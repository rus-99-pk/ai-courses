# Модуль 2: Создание базового chroot-окружения

Это самый важный модуль. Здесь мы научимся создавать минимальное, но рабочее `chroot`-окружение с нуля. Все команды нужно выполнять с правами `root` или через `sudo`.

**Наша цель**: создать окружение, в которое можно войти и выполнить команду `ls -l`.

### Шаг 1: Создание корневого каталога

Это будет наш новый "корень".

```bash
# Создаем директорию для нашего chroot
sudo mkdir /mnt/mychroot
```

### Шаг 2: Создание базовой структуры каталогов

Внутри нашего окружения тоже нужны привычные каталоги, как в настоящей системе.

```bash
# Создаем каталоги для бинарных файлов и библиотек
sudo mkdir -p /mnt/mychroot/{bin,lib,lib64}
```
*   `bin`: для исполняемых файлов (`bash`, `ls`).
*   `lib`, `lib64`: для библиотек, от которых зависят эти программы.

### Шаг 3: Копирование необходимых программ

Скопируем `bash` (чтобы иметь командную строку) и `ls` (чтобы что-то выполнить).

```bash
# Копируем исполняемые файлы
sudo cp /bin/bash /mnt/mychroot/bin/
sudo cp /bin/ls /mnt/mychroot/bin/
```

### Шаг 4: Копирование зависимостей (самый важный шаг!)

Программы не работают сами по себе. Им нужны библиотеки (`.so` файлы). Как узнать, какие? С помощью команды `ldd`.

```bash
# Смотрим зависимости для bash
ldd /bin/bash
```
Вывод будет примерно таким (может отличаться в вашей системе):
```
	linux-vdso.so.1 (0x00007ffc...)
	libtinfo.so.6 => /lib/x86_64-linux-gnu/libtinfo.so.6 (0x00007f3b...)
	libdl.so.2 => /lib/x86_64-linux-gnu/libdl.so.2 (0x00007f3b...)
	libc.so.6 => /lib/x86_64-linux-gnu/libc.so.6 (0x00007f3b...)
	/lib64/ld-linux-x86-64.so.2 (0x00007f3b...)
```
Нам нужно скопировать все файлы, которые указаны после `=>`, а также загрузчик (`/lib64/ld-linux-x86-64.so.2`).

```bash
# Копируем зависимости для bash
sudo cp /lib/x86_64-linux-gnu/libtinfo.so.6 /mnt/mychroot/lib/
sudo cp /lib/x86_64-linux-gnu/libdl.so.2 /mnt/mychroot/lib/
sudo cp /lib/x86_64-linux-gnu/libc.so.6 /mnt/mychroot/lib/
sudo cp /lib64/ld-linux-x86-64.so.2 /mnt/mychroot/lib64/
```
> ⚠️ **Внимание!** Пути к библиотекам могут отличаться. Всегда используйте вывод `ldd` из вашей системы. `/lib/x86_64-linux-gnu` — это частый путь для Debian/Ubuntu. В CentOS/Fedora это может быть `/lib64`.

Теперь повторим то же самое для `ls`:
```bash
# Смотрим и копируем зависимости для ls
ldd /bin/ls
# ... (скопируйте недостающие библиотеки по аналогии)
```
Некоторые библиотеки могут совпадать, их не нужно копировать повторно.

### Шаг 5: Вход в chroot-окружение

Все готово для первого входа!

```bash
# Выполняем chroot
sudo chroot /mnt/mychroot /bin/bash
```

Если все сделано правильно, ваше приглашение командной строки изменится, и вы окажетесь внутри "тюрьмы".

### Шаг 6: Проверка

Попробуем выполнить команду `ls -l` внутри chroot.

```bash
# Находясь внутри chroot
ls -l /
```
Вы должны увидеть содержимое `/mnt/mychroot`, а не корень вашей основной системы:
```
drwxr-xr-x 2 root root 4096 Nov 10 12:00 bin
drwxr-xr-x 2 root root 4096 Nov 10 12:01 lib
drwxr-xr-x 2 root root 4096 Nov 10 12:01 lib64
```
Чтобы выйти из chroot, просто введите команду `exit`.

```bash
exit
```

---
**Что дальше?** Наше окружение работает, но оно очень ограничено. Например, в нем не работают `ping` или `ps`. Чтобы это исправить, нужно добавить виртуальные файловые системы.
