# Модуль 4: Практические задачи

Теория — это хорошо, но `chroot` раскрывает свою силу при решении конкретных проблем.

### Задача 1: Восстановление загрузчика GRUB

**Сценарий**: Ваша система Linux перестала загружаться после установки Windows или неудачного обновления. Загрузчик GRUB поврежден.

**Решение**: Мы загрузимся с LiveUSB/LiveCD, сделаем `chroot` в нашу установленную систему и восстановим GRUB изнутри.

**Команды-методичка**:

1.  **Загрузитесь с LiveUSB** (например, Ubuntu, Mint, Arch).

2.  **Определите ваш корневой раздел**. Используйте `lsblk` или `fdisk -l`. Допустим, это `/dev/sda2`.

    ```bash
    sudo lsblk
    # NAME   MAJ:MIN RM   SIZE RO TYPE MOUNTPOINT
    # sda      8:0    0 238.5G  0 disk
    # ├─sda1   8:1    0   512M  0 part /boot/efi  <-- EFI раздел
    # └─sda2   8:2    0   238G  0 part /          <-- Корневой раздел
    ```

3.  **Примонтируйте корневой раздел** системы.

    ```bash
    # Создаем временную точку монтирования
    sudo mkdir /mnt/system
    # Монтируем корневой раздел
    sudo mount /dev/sda2 /mnt/system
    ```

4.  **(Для UEFI систем)** Примонтируйте EFI-раздел.

    ```bash
    # Если у вас есть EFI раздел (например, /dev/sda1)
    sudo mount /dev/sda1 /mnt/system/boot/efi
    ```

5.  **Примонтируйте виртуальные ФС**, как мы делали в прошлом модуле.

    ```bash
    sudo mount --bind /dev /mnt/system/dev
    sudo mount --bind /proc /mnt/system/proc
    sudo mount --bind /sys /mnt/system/sys
    ```
    
6.  **Сделайте Chroot**. Теперь мы "внутри" нашей сломанной системы.

    ```bash
    sudo chroot /mnt/system
    ```

7.  **Восстановите GRUB**.

    ```bash
    # Внутри chroot
    
    # Переустанавливаем GRUB на диск sda (не на раздел!)
    grub-install /dev/sda

    # Обновляем конфигурацию GRUB, чтобы он нашел все ОС
    update-grub
    
    # Выходим из chroot
    exit
    ```

8.  **Размонтируйте все** и перезагружайтесь.

    ```bash
    # В основной системе LiveUSB
    sudo umount -R /mnt/system
    sudo reboot
    ```
    Ваша система должна загрузиться.

### Задача 2: Создание изолированной SFTP-"тюрьмы"

**Сценарий**: Вы хотите дать пользователю `testuser` доступ к серверу по SFTP, но ограничить его только его домашней директорией (`/home/testuser`), чтобы он не мог просматривать остальную файловую систему.

**Решение**: Мы используем встроенную в OpenSSH-сервер функциональность `ChrootDirectory`.

**Команды-методичка**:

1.  **Создайте пользователя** (если его еще нет).

    ```bash
    sudo adduser testuser
    ```

2.  **Настройте OpenSSH сервер**. Откройте файл `/etc/ssh/sshd_config`.

    ```bash
    sudo nano /etc/ssh/sshd_config
    ```

3.  **Добавьте в конец файла** следующие строки:

    ```apacheconf
    # Этот блок должен быть в самом конце файла
    Match User testuser
        # Указываем, что /home/testuser будет корнем для этого пользователя
        ChrootDirectory /home/testuser
        # Принудительно используем внутренний SFTP-сервер OpenSSH
        ForceCommand internal-sftp
        # Запрещаем туннелирование портов и X11
        AllowTcpForwarding no
        X11Forwarding no
    ```
    
4.  **Настройте права доступа (КРИТИЧЕСКИ ВАЖНО!)**.
    `sshd` требует, чтобы каталог chroot и все его родительские каталоги принадлежали `root` и не были доступны для записи никому другому.

    *   Корневой каталог chroot (`/home/testuser`) должен принадлежать `root`.
    *   Пользователь `testuser` не сможет писать в свою домашнюю директорию. Это неудобно.

    **Правильное решение**: создать внутри подкаталог, в который пользователь сможет загружать файлы.

    ```bash
    # Меняем владельца домашней директории на root
    sudo chown root:root /home/testuser
    
    # Запрещаем запись всем, кроме владельца (root)
    sudo chmod 755 /home/testuser
    
    # Создаем внутри каталог для загрузки файлов
    sudo mkdir /home/testuser/upload
    
    # Делаем пользователя владельцем этого каталога
    sudo chown testuser:testuser /home/testuser/upload
    ```
    Теперь `testuser` при входе по SFTP окажется в `/`, но это будет `/home/testuser`. Он сможет видеть каталог `upload` и загружать файлы туда.

5.  **Перезапустите SSH-сервер**, чтобы применить изменения.

    ```bash
    sudo systemctl restart sshd
    ```

6.  **Проверьте**, подключившись по SFTP.

    ```bash
    sftp testuser@your_server_ip
    # Попробуйте выполнить команду "ls /" - вы увидите только то, что в /home/testuser.
    # Попробуйте "cd .." - вы не сможете выйти за пределы chroot.
    ```

---
**Что дальше?** Мы увидели `chroot` в действии. Но важно понимать его слабые стороны.
