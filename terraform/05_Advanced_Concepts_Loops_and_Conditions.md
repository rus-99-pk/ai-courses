# Тема 5: Продвинутые концепции: циклы и условия

## Какую проблему мы решаем?

В прошлом уроке мы создали два сервера, скопировав блок `module`. Это сработало для двух, но что, если нам нужно 10 одинаковых ресурсов? Или если нам нужно создать ресурс только при определенном условии (например, создать публичный IP-адрес только для `prod` окружения, но не для `dev`)?

Копирование кода (`copy-paste`) приводит к его раздуванию и усложняет поддержку. Отсутствие условной логики заставляет нас создавать разные конфигурации для разных окружений, хотя они на 95% совпадают.

### Задача:
1.  С помощью **цикла** создать несколько S3 бакетов на основе списка имен.
2.  С помощью **условия** создать дополнительный ресурс (политику доступа) только для одного из этих бакетов.

## Концепция 1: Циклы (`for_each`)

Самый мощный и предпочтительный способ создания нескольких экземпляров ресурса в Terraform — это мета-аргумент `for_each`. Он итерируется по **карте (map)** или **множеству (set)** и создает по одному экземпляру ресурса для каждого элемента.

**Почему `for_each` лучше, чем `count`?**
Старый способ — `count = 3` — создавал ресурсы с индексами `[0]`, `[1]`, `[2]`. Если вы удаляли элемент из середины списка, Terraform сдвигал индексы и хотел пересоздать все последующие ресурсы. `for_each` использует ключи (`"dev"`, `"prod"`), и при удалении одного элемента остальные не затрагиваются. **Всегда предпочитайте `for_each`**, когда это возможно.

## Концепция 2: Условия

В Terraform нет прямого `if/else` для создания ресурсов. Вместо этого используются два основных подхода:

1.  **Тернарный оператор с `count`**:
    Это классический способ. Мы устанавливаем `count` в `1`, если условие истинно, и в `0`, если ложно.
    ```hcl
    resource "aws_eip" "prod_ip" {
      # Создаем ресурс, только если is_production_env == true
      count = var.is_production_env ? 1 : 0
      # ...
    }
    ```

2.  **Фильтрация в цикле `for_each`**:
    Более современный и гибкий способ. Мы можем отфильтровать нашу карту или множество перед передачей в `for_each`.
    ```hcl
    # Создать бакеты только для окружений, помеченных как "active"
    locals {
      active_environments = {
        for env, config in var.environments : env => config if config.is_active
      }
    }

    resource "aws_s3_bucket" "env_buckets" {
      for_each = local.active_environments
      # ...
    }
    ```

## Практика: Создание S3 бакетов с условной политикой

Создадим новую директорию проекта.

### `variables.tf`
```hcl
variable "department_names" {
  description = "Список названий отделов для создания S3 бакетов"
  type        = list(string)
  default     = ["marketing", "sales", "finance"]
}

variable "main_bucket_name" {
  description = "Имя главного бакета, которому нужна особая политика"
  type        = string
  default     = "finance"
}
```

### `main.tf`
```hcl
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 4.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

# Используем for_each для создания бакетов для каждого отдела.
# toset() преобразует список (list) в множество (set), что необходимо для for_each.
resource "aws_s3_bucket" "department_buckets" {
  for_each = toset(var.department_names)

  # each.key и each.value в данном случае будут одинаковыми (имя отдела)
  bucket = "tf-course-bucket-${each.key}-${random_id.suffix.hex}"

  tags = {
    Department = each.key
  }
}

# Этот ресурс нужен, чтобы имена бакетов были уникальными при каждом запуске
resource "random_id" "suffix" {
  byte_length = 4
}


# УСЛОВНЫЙ РЕСУРС:
# Создаем политику, которая запрещает удаление,
# но только для бакета, указанного в var.main_bucket_name.
resource "aws_s3_bucket_policy" "prevent_deletion" {
  # Мы создаем карту с одним элементом (если условие выполнено)
  # или с нулем элементов (если не выполнено).
  # for_each ничего не создаст для пустой карты.
  for_each = {
    for bucket_name in toset(var.department_names) : bucket_name => ""
    if bucket_name == var.main_bucket_name
  }

  # `each.key` здесь будет равен значению var.main_bucket_name
  bucket = aws_s3_bucket.department_buckets[each.key].id

  policy = jsonencode({
    Version = "2012-10-17",
    Statement = [
      {
        Sid       = "DenyDeleteObject",
        Effect    = "Deny",
        Principal = "*",
        Action    = "s3:DeleteObject",
        Resource  = "${aws_s3_bucket.department_buckets[each.key].arn}/*"
      }
    ]
  })
}
```
*Примечание: `random_id` — это утилитарный ресурс, который генерирует случайную строку. Мы используем его, чтобы избежать конфликтов имен S3 бакетов, которые должны быть глобально уникальными.*

## Команда-методичка

1.  **Инициализация**:
    ```bash
    terraform init
    ```
    *Terraform скачает провайдеры `aws` и `random`.*

2.  **Планирование**:
    ```bash
    terraform plan
    ```
    *Ожидаемый результат*: План покажет создание 3-х S3 бакетов (`"marketing"`, `"sales"`, `"finance"`) и **одной** политики `aws_s3_bucket_policy`, которая будет привязана к бакету `finance`. `Plan: 5 to add...` (3 бакета + 1 политика + 1 random_id).

3.  **Применение**:
    ```bash
    terraform apply --auto-approve
    ```
    *Ожидаемый результат*: Все ресурсы будут созданы.

4.  **Эксперимент**:
    Попробуйте изменить переменную и применить снова.
    ```bash
    terraform apply --auto-approve -var='main_bucket_name=marketing'
    ```
    *Ожидаемый результат*: Terraform увидит, что условие для политики изменилось. Он **уничтожит** старую политику (у бакета `finance`) и **создаст** новую для бакета `marketing`. Сами бакеты при этом затронуты не будут.

5.  **Уничтожение**:
    ```bash
    # Попытка удалить все ресурсы
    terraform destroy --auto-approve
    ```
    *Ожидаемый результат*: Вы получите **ошибку**! Terraform не сможет удалить бакет `finance` (или `marketing`, в зависимости от последнего apply), потому что созданная нами политика это запрещает. Это доказывает, что наша условная политика работает.
    Чтобы успешно всё удалить, вам нужно сначала удалить политику (например, закомментировав ресурс `aws_s3_bucket_policy` и запустив `apply`), а затем уже запустить `destroy`.

Вы освоили одни из самых мощных инструментов Terraform для создания гибких и масштабируемых конфигураций!
