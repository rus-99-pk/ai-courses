# 02 - Развертывание первого приложения

### Цель урока
Научиться создавать `Application` в ArgoCD, чтобы развернуть простое приложение из Git-репозитория. Мы сделаем это двумя способами: через веб-интерфейс и через CLI.

### Какую проблему решаем?
У нас есть готовые Kubernetes-манифесты в Git, но мы до сих пор применяли их вручную командой `kubectl apply`. Это медленно, подвержено ошибкам и лишено прозрачности. Мы хотим автоматизировать этот процесс.

### Подготовка: Репозиторий с приложением

Для этого урока мы будем использовать официальный репозиторий с примерами от ArgoCD. В нем есть простое приложение `guestbook`, которое состоит из `Deployment` и `Service`.

*   **URL репозитория:** `https://github.com/argoproj/argocd-example-apps.git`
*   **Путь к приложению:** `guestbook`

Вам не нужно клонировать этот репозиторий, ArgoCD будет работать с ним напрямую.

### Практика 1: Создание приложения через Web UI

Это самый наглядный способ для новичков.

1.  **Войдите в UI ArgoCD** (не забудьте про `kubectl port-forward`, если еще не сделали).
2.  Нажмите на кнопку **+ NEW APP**.
3.  Заполните форму:
    *   **Application Name**: `guestbook` (или любое другое имя)
    *   **Project Name**: `default` (пока используем проект по умолчанию)
    *   **Sync Policy**: `Manual` (мы будем запускать синхронизацию вручную для контроля)

4.  **Источник (Source)**:
    *   **Repository URL**: `https://github.com/argoproj/argocd-example-apps.git`
    *   **Revision**: `HEAD` (означает последнюю версию в основной ветке)
    *   **Path**: `guestbook` (указываем папку с нашими манифестами)

5.  **Назначение (Destination)**:
    *   **Cluster URL**: `https://kubernetes.default.svc` (это специальное имя для кластера, в котором работает сам ArgoCD)
    *   **Namespace**: `guestbook` (укажем новый неймспейс, ArgoCD создаст его, если он не существует)

6.  Нажмите кнопку **CREATE** вверху.

Вы увидите карточку нового приложения со статусом `Missing` и `OutOfSync`.
*   `Missing` означает, что приложение еще не создано в кластере.
*   `OutOfSync` означает, что состояние в кластере (ничего) отличается от желаемого состояния в Git (Deployment и Service).

7.  **Синхронизация:**
    *   Нажмите на карточку приложения `guestbook`.
    *   Нажмите кнопку **SYNC**.
    *   В появившемся окне можно посмотреть, какие ресурсы будут созданы. Нажмите **SYNCHRONIZE**.

Процесс синхронизации займет несколько секунд. После этого статусы изменятся на `Healthy` и `Synced`. Это означает, что ArgoCD успешно развернул ваше приложение!

**Проверка в кластере:**
```bash
kubectl get all -n guestbook
```
Вы должны увидеть `Deployment`, `ReplicaSet`, `Pod` и `Service` для вашего приложения.

### Практика 2: Создание приложения через CLI

Удалим приложение, созданное через UI, и повторим то же самое с помощью командной строки.

1.  **Удаление приложения:**
    ```bash
    # Убедитесь, что вы залогинены через CLI (argocd login ...)
    argocd app delete guestbook
    ```

2.  **Создание приложения:**
    Команда `argocd app create` принимает те же параметры, что и форма в UI.

    ```bash
    argocd app create guestbook-cli \
      --repo https://github.com/argoproj/argocd-example-apps.git \
      --path guestbook \
      --dest-server https://kubernetes.default.svc \
      --dest-namespace guestbook
    ```
    *Мы назвали его `guestbook-cli`, чтобы не было путаницы.*

3.  **Проверка статуса:**
    ```bash
    argocd app get guestbook-cli
    ```
    Вы увидите подробную информацию о приложении, включая статус `OutOfSync`.

4.  **Синхронизация:**
    ```bash
    argocd app sync guestbook-cli
    ```
    Команда запросит подтверждение и выполнит синхронизацию.

5.  **Проверка:**
    Снова проверьте статус через `argocd app get guestbook-cli` или `kubectl get all -n guestbook`. Приложение снова развернуто!

### Команды-методички

```bash
# Создать приложение через CLI
argocd app create <имя-приложения> \
  --repo <URL-репозитория> \
  --path <путь-к-манифестам> \
  --dest-server <URL-кластера-назначения> \
  --dest-namespace <неймспейс-назначения>

# Пример:
argocd app create guestbook-cli \
  --repo https://github.com/argoproj/argocd-example-apps.git \
  --path guestbook \
  --dest-server https://kubernetes.default.svc \
  --dest-namespace guestbook

# Получить список всех приложений
argocd app list

# Получить детальную информацию о приложении
argocd app get <имя-приложения>

# Синхронизировать приложение (применить изменения из Git)
argocd app sync <имя-приложения>

# Посмотреть историю синхронизаций
argocd app history <имя-приложения>

# Удалить приложение (с удалением его ресурсов из кластера по умолчанию)
argocd app delete <имя-приложения>
```
Поздравляю! Вы освоили базовый цикл работы с ArgoCD. В следующих уроках мы разберем более сложные концепции.
