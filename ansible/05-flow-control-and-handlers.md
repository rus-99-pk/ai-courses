# Тема 5: Управление потоком, условия и обработчики

## Задача, которую мы решаем

Наши плейбуки становятся сложнее. Возникают новые потребности:
1.  **Проблема с конфигурацией:** Мы скопировали файл `index.html`. Но что если мы захотим поменять конфигурационный файл Nginx, например, `/etc/nginx/nginx.conf`? После копирования нового файла конфигурации Nginx не узнает об изменениях, пока мы его не перезапустим. Ручной перезапуск после плейбука — плохая практика.
2.  **Проблема с универсальностью:** Наш плейбук использует модуль `apt` и жестко привязан к Debian/Ubuntu. Как сделать так, чтобы он работал и на CentOS, где используется `yum`?
3.  **Проблема с однотипными действиями:** Что, если нам нужно установить не один, а сразу пять пакетов (`nginx`, `curl`, `vim`, `htop`, `git`)? Создавать пять отдельных задач — неэффективно.

**Решение:**
1.  Использовать **обработчики (handlers)**, которые выполняются только тогда, когда задача вносит изменения.
2.  Использовать **условия (`when`)** для выполнения задач только на определенных ОС.
3.  Использовать **циклы (`loop`)** для выполнения одной задачи с разными данными.

---

### 1. Обработчики (Handlers)

**Handler** — это особая задача, которая запускается только по вызову от другой задачи с помощью директивы `notify`. Главная особенность: хендлер будет вызван **только если** задача-уведомитель имела статус `changed`. Он также выполняется только один раз в конце всего плейбука, даже если его вызвали несколько задач.

Идеально для перезапуска сервисов.

#### Методичка: Добавляем хендлер для перезапуска Nginx

1.  **Создайте простой файл конфигурации `my_nginx.conf`:**
    ```nginx
    # Это просто пример, не обязательно рабочая конфигурация
    user www-data;
    worker_processes auto;
    pid /run/nginx.pid;
    ```

2.  **Обновите плейбук `install_nginx.yml`:**
    Мы добавим задачу для копирования этого файла и свяжем её с хендлером.

    ```yaml
    ---
    - name: Install and configure Webserver
      hosts: webservers
      become: yes

      vars:
        web_package: nginx

      tasks:
        # ... (задачи установки nginx и service)

        - name: Copy custom Nginx configuration
          ansible.builtin.copy:
            src: my_nginx.conf
            dest: /etc/nginx/conf.d/my_site.conf
            owner: root
            group: root
            mode: '0644'
          notify: Restart Nginx # Имя хендлера, которое мы вызываем

      # Новая секция для хендлеров
      handlers:
        - name: Restart Nginx # Имя, на которое ссылается notify
          ansible.builtin.service:
            name: "{{ web_package }}"
            state: restarted
    ```
    **Как это работает:**
    *   При первом запуске плейбука, `ansible.builtin.copy` скопирует файл, получит статус `changed` и "уведомит" хендлер `Restart Nginx`. В конце плейбука Nginx перезапустится.
    *   При повторном запуске, `ansible.builtin.copy` увидит, что файл не изменился, получит статус `ok` и **не будет** вызывать хендлер. Nginx не будет перезапущен без необходимости!

### 2. Условия (`when`)

Директива `when` позволяет выполнять задачу только при выполнении определенного условия. Часто используется для работы с разными операционными системами, проверяя факт `ansible_os_family`.

#### Методичка: Универсальный плейбук для Debian и RedHat

```yaml
# Фрагмент плейбука
# ...
tasks:
  - name: Install web package on Debian-based systems
    ansible.builtin.apt:
      name: "{{ web_package }}"
      state: present
    when: ansible_os_family == "Debian"

  - name: Install web package on RedHat-based systems
    ansible.builtin.yum:
      name: "{{ web_package_redhat | default('httpd') }}" # Используем переменную для RedHat
      state: present
    when: ansible_os_family == "RedHat"
```
**Как это работает:**
*   Первая задача выполнится только на хостах, где `ansible_os_family` равно "Debian" (Ubuntu, Mint).
*   Вторая задача — только там, где `ansible_os_family` равно "RedHat" (CentOS, RHEL, Fedora).

### 3. Циклы (`loop`)

Директива `loop` позволяет выполнить одну и ту же задачу несколько раз с разными элементами из списка.

#### Методичка: Установка нескольких пакетов в цикле

Вместо пяти задач для установки `nginx`, `curl`, `vim`, `htop`, `git`, мы сделаем одну.

```yaml
# Фрагмент плейбука
# ...
vars:
  required_packages:
    - nginx
    - curl
    - vim
    - htop
    - git

tasks:
  - name: Install common packages
    ansible.builtin.apt:
      name: "{{ item }}"
      state: present
    loop: "{{ required_packages }}" # Перебираем список
```
**Как это работает:**
*   Ansible выполнит задачу `ansible.builtin.apt` для каждого элемента из списка `required_packages`.
*   `{{ item }}` — это специальная переменная, которая на каждой итерации цикла содержит текущий элемент (`nginx`, потом `curl` и т.д.).
