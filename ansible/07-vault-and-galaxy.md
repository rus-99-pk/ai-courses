# Тема 7: Продвинутые темы: Ansible Vault и Galaxy

## Задача, которую мы решаем

Мы научились структурировать код с помощью ролей, но остались две важные проблемы:
1.  **Безопасность:** Что, если нам нужно в плейбуке указать пароль от базы данных, API-ключ или SSL-сертификат? Хранить их в открытом виде в Git-репозитории — это катастрофа с точки-зрения безопасности.
2.  **Эффективность:** Мы написали роль для Nginx. Но ведь кто-то уже наверняка написал отличную, протестированную сообществом роль для установки PostgreSQL, Redis или Prometheus. Зачем изобретать велосипед?

**Решение:**
1.  Использовать **Ansible Vault** для шифрования чувствительных данных (файлов или отдельных переменных).
2.  Использовать **Ansible Galaxy** — репозиторий готовых ролей от сообщества — для поиска и установки готовых решений.

---

### 1. Ansible Vault: Безопасное хранение секретов

**Ansible Vault** — это инструмент, встроенный в Ansible, который позволяет шифровать файлы целиком или отдельные строки. Зашифрованные файлы можно безопасно хранить в системе контроля версий. Ansible сможет их расшифровать "на лету" во время выполнения плейбука, если вы предоставите пароль.

#### Методичка: Шифруем файл с переменными

Представим, что у нас есть секреты для базы данных.

1.  **Создайте файл `secrets.yml`:**
    ```yaml
    db_user: my_secret_user
    db_password: "SuperSecretPassword123!"
    ```

2.  **Зашифруйте этот файл с помощью `ansible-vault encrypt`:**
    ```bash
    # Методичка
    ansible-vault encrypt secrets.yml
    ```
    Система попросит вас дважды ввести пароль. Запомните его! После этого содержимое файла `secrets.yml` превратится в зашифрованный текст:
    ```
    $ANSIBLE_VAULT;1.1;AES256
    36343431633461323933623...
    ```
    Теперь этот файл можно спокойно коммитить в Git.

3.  **Как использовать зашифрованный файл в плейбуке?**
    В основном плейбуке (`site.yml`) добавьте секцию `vars_files`, чтобы подключить этот файл.

    ```yaml
    # site.yml
    ---
    - name: Configure Servers
      hosts: all
      become: yes
      
      vars_files:
        - secrets.yml  # Подключаем зашифрованный файл

      roles:
        - webserver
        # - database_role # (гипотетическая роль, использующая db_user и db_password)
    ```

4.  **Как запустить плейбук с зашифрованным файлом?**
    При запуске нужно передать пароль. Есть два способа:

    *   **Интерактивный (рекомендуется):** Ansible сам спросит пароль.
        ```bash
        # Методичка
        ansible-playbook -i inventory.ini site.yml --ask-vault-pass
        ```

    *   **Через файл (для CI/CD):** Сохраните пароль в текстовый файл (`.vault_pass`), ограничьте права на него (`chmod 600 .vault_pass`) и укажите путь к нему. **Не коммитьте этот файл в Git!** Добавьте его в `.gitignore`.
        ```bash
        # Методичка
        ansible-playbook -i inventory.ini site.yml --vault-password-file .vault_pass
        ```

**Другие команды Vault:**
*   `ansible-vault edit secrets.yml`: Редактировать зашифрованный файл (он временно расшифруется).
*   `ansible-vault decrypt secrets.yml`: Расшифровать файл обратно в текст.
*   `ansible-vault view secrets.yml`: Посмотреть содержимое, не расшифровывая файл на диске.

### 2. Ansible Galaxy: Репозиторий готовых ролей

**Ansible Galaxy** — это и команда, и публичный хаб (https://galaxy.ansible.com), где можно найти тысячи готовых ролей.

#### Методичка: Установка и использование роли для Nginx от сообщества

Давайте не будем использовать нашу самописную роль `webserver`, а возьмем популярную роль от сообщества.

1.  **Найдите роль на Ansible Galaxy.**
    Например, `nginxinc.nginx` — это официальная роль от разработчиков Nginx.

2.  **Установите роль с помощью `ansible-galaxy`:**
    Роли по умолчанию устанавливаются в системную директорию или в `~/.ansible/roles`. Чтобы установить их локально в наш проект, создадим файл `requirements.yml`.

    *   **Создайте файл `requirements.yml`:**
        ```yaml
        ---
        roles:
          - name: nginxinc.nginx
            # version: 0.23.2 # Можно указать конкретную версию
        ```

    *   **Установите роли из файла:**
        ```bash
        # Методичка: установить роли в локальную папку roles/
        ansible-galaxy install -r requirements.yml -p ./roles
        ```
        Вы увидите, что в папку `roles` скачалась роль `nginxinc.nginx`.

3.  **Используйте установленную роль в плейбуке `site.yml`:**
    Замените нашу старую роль `webserver` на новую.

    ```yaml
    ---
    - name: Configure Webservers
      hosts: webservers
      become: yes
      
      roles:
        - nginxinc.nginx
    ```
    *Важно: у каждой роли от сообщества есть своя документация (обычно на странице Galaxy или в `README.md` внутри роли). Там описано, какие переменные можно использовать для её настройки.* Например, чтобы изменить порт, вы можете определить переменную в плейбуке:
    ```yaml
    # ...
    vars:
      nginx_listen_port: 8080 # Это переменная из документации к роли nginxinc.nginx

    roles:
      - nginxinc.nginx
    ```

**Использование Galaxy** — это ключевой навык для продуктивной работы с Ansible. Он позволяет вам концентрироваться на уникальной логике вашего приложения, а не на базовой настройке стандартного ПО.
