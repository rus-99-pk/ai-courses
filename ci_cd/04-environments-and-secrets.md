# Тема 4: Окружения и Секреты

## Какую проблему решаем?

В прошлом уроке мы столкнулись с необходимостью указывать логин и пароль (`DOCKERHUB_TOKEN`) для доступа к Docker Hub. **Хранить чувствительные данные (токены, пароли, ключи API) прямо в `.yml` файле — это огромная дыра в безопасности.**

Нам нужен механизм для безопасного хранения таких данных и их использования в CI/CD.

*   **Секреты (Secrets)**: Для хранения чувствительной информации. Они не отображаются в логах.
*   **Переменные (Variables)**: Для хранения нечувствительной конфигурации (например, имя домена для dev-среды).
*   **Окружения (Environments)**: Для группировки секретов и переменных под конкретную среду (`staging`, `production`) и для защиты деплоя (например, требовать подтверждения).

### Задача

1.  Создать секрет `SUPER_SECRET_KEY` со значением `123456789`.
2.  Использовать его в CI/CD пайплайне так, чтобы в логах его значение не отображалось.

---

### GitLab CI

В GitLab для этого используются **CI/CD Variables**.

**Где настраивать:**
1.  Зайдите в ваш проект на GitLab.
2.  Перейдите в `Settings -> CI/CD`.
3.  Разверните секцию `Variables`.
4.  Нажмите `Add variable`.
5.  **Key**: `SUPER_SECRET_KEY`
6.  **Value**: `123456789`
7.  **Flags**: Поставьте галочку `Protect variable` (будет доступна только в защищенных ветках/тегах) и `Mask variable` (будет заменена на `[MASKED]` в логах).
8.  Нажмите `Add variable`.

**Использование в `.gitlab-ci.yml`:**

```yml
# .gitlab-ci.yml

stages:
  - secrets_test

test_secrets_job:
  stage: secrets_test
  script:
    - echo "Давай попробуем вывести секрет..."
    - echo "Мой секретный ключ: $SUPER_SECRET_KEY"
    - echo "Эта команда тоже использует секрет: my_command --api-key=$SUPER_SECRET_KEY"
```

**Разбор команд:**
*   В GitLab переменные и секреты используются одинаково — как обычные переменные окружения в Linux (`$VARIABLE_NAME`).
*   Если вы правильно настроили маскирование, то в логе выполнения задачи вы увидите `Мой секретный ключ: [MASKED]`.

### GitHub Actions

В GitHub есть разделение на **Secrets** (для чувствительных данных) и **Variables** (для открытых).

**Где настраивать:**
1.  Зайдите в ваш репозиторий на GitHub.
2.  Перейдите в `Settings`.
3.  В меню слева выберите `Secrets and variables -> Actions`.
4.  Переключитесь на вкладку `Secrets` и нажмите `New repository secret`.
5.  **Name**: `SUPER_SECRET_KEY`
6.  **Secret**: `123456789`
7.  Нажмите `Add secret`.

**Использование в `.github/workflows/main.yml`:**

```yml
# .github/workflows/main.yml
name: Secrets Test

on:
  push:
    branches: [ "main" ]

jobs:
  test_secrets_job:
    runs-on: ubuntu-latest
    steps:
      - name: Use the secret
        # Секреты передаются через объект `secrets`
        # Они автоматически маскируются в логах
        run: |
          echo "Давай попробуем вывести секрет..."
          echo "Мой секретный ключ: ${{ secrets.SUPER_SECRET_KEY }}"
          echo "Эта команда тоже использует секрет: my_command --api-key=${{ secrets.SUPER_SECRET_KEY }}"
```

**Разбор команд:**
*   Секреты в GitHub Actions доступны через специальный объект `secrets`.
*   Синтаксис: `${{ secrets.SECRET_NAME }}`.
*   GitHub автоматически пытается найти и замаскировать значение секрета в логах, где бы оно ни появилось.
*   **Важно:** Не путайте синтаксис. В GitLab `$VAR`, в GitHub `${{ secrets.VAR }}`.
