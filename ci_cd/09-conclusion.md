## Куда двигаться дальше?

Мир DevOps и CI/CD огромен. Вот несколько направлений для дальнейшего изучения:

1.  **Безопасность (DevSecOps)**
    *   **SAST (Static Application Security Testing)**: Инструменты (например, SonarQube, Snyk, встроенные сканеры GitLab/GitHub), которые анализируют ваш исходный код на наличие уязвимостей.
    *   **Dependency Scanning**: Автоматическая проверка ваших зависимостей (`node_modules`, `pip` пакеты) на известные уязвимости. GitHub Dependabot и GitLab Dependency Scanning делают это "из коробки".
    *   **DAST (Dynamic Application Security Testing)**: Сканирование уже запущенного приложения на наличие уязвимостей.

2.  **Инфраструктура как Код (Infrastructure as Code, IaC)**
    *   CI/CD — это идеальное место для запуска таких инструментов, как **Terraform** или **Ansible**. Вместо ручной настройки серверов вы описываете их в коде, а CI/CD-пайплайн применяет эти изменения.
    *   *Пример*: Пайплайн, который при коммите в `main` запускает `terraform apply` для обновления вашей облачной инфраструктуры на AWS, Google Cloud или Azure.

3.  **Развертывание в Kubernetes**
    *   Kubernetes (K8s) — это стандарт де-факто для оркестрации контейнеров. Следующим шагом после сборки Docker-образа часто является его деплой в K8s-кластер с помощью `kubectl` или **Helm**.

4.  **Продвинутые возможности платформ**
    *   **GitLab**: Изучите `parent-child pipelines` для более сложных и динамических пайплайнов, а также Auto DevOps для получения полного цикла CI/CD из коробки.
    *   **GitHub Actions**: Познакомьтесь с `reusable workflows` для переиспользования логики между разными репозиториями и создайте свои собственные Actions.

5.  **Мониторинг и Наблюдаемость (Observability)**
    *   CI/CD — это не конец цикла. После деплоя важно знать, как работает ваше приложение. Изучите, как интегрировать в ваш процесс инструменты вроде **Prometheus**, **Grafana**, **Datadog** или **Sentry**.
